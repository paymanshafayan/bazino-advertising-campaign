# استودیوی تبلیغات و بازاریابی

فضای کاری ایجنت متخصص تبلیغات و بازاریابی بازینو برای تحقیق، طراحی کمپین، آماده‌سازی محتوا، بازبینی و گزارشِ متکی به شاهد. این پوشه روی شاخهٔ کاری خودِ ایجنت نگهداری می‌شود؛ مستندات انتقالی اینجا **به‌معنی فعال‌شدن کمپین یا اتصال به حساب‌ها نیستند**.

## از اینجا شروع کنید

1. **[HANDOFF.md](HANDOFF.md):** قواعد صریح مالک، تصمیم‌های قابل انتقال از پروژهٔ قدیمی با تاریخ/دامنهٔ اعتبار، وضعیت قابل اتکا و مرزهای دسترسی این نشست.
2. **[SKILL.md](SKILL.md):** مأموریت بازاریابی، گردش کار و تفکیک کانال‌ها/کمپین‌ها؛ برای اجرای تخصصی از [نمایهٔ دانش](knowledge/README.md) منبع مرتبط را انتخاب کنید.
3. **[الگوهای کاری](playbooks/work-patterns.md)** و **[قالب‌های خروجی](playbooks/output-templates.md):** تجربه‌های اجرایی با وضعیت آزمون، کنترل کیفیت و نمونهٔ تحویل؛ دستور انتشار نیستند.
4. **[تولید ویدئو](knowledge/video-production/SKILL.md)** و **[سنجش و یادگیری](knowledge/measurement-and-learning/SKILL.md):** دانش موضوعیِ انتقال‌یافته با انتساب/منشأ و حدود اعتبار.
5. **[برنامهٔ بازاریابی Windows بدون Electron](desktop-app/README.md):** Zernio برای شبکه‌ها، FLUX از Vault سمت سرور پورتال، Kling MCP با OAuth؛ و گیت قابل‌پیکربندی API/MCP راه‌دور و استخراج متن URL عمومی بدون نصب مجدد برای هر سرویس. توکن سرویس جدید فقط در UI محلی مالک است. برای دورزدن محدودیت آپلود artifact، [اسکریپت ساخت محلی PowerShell](desktop-app/build-local.ps1) نیز برای استودیو و پل جداگانه آماده شده؛ اجرای آن روی Windows هنوز تأیید نشده است. آپلودهای بعدی GitHub با وجود پاک‌بودن artifact/cache همچنان خطای سهمیه داده‌اند. اجرای حساب‌ها/انتشار واقعی و اینترنت/DPAPI گیت هنوز تأیید نشده است.
6. **[ماتریس اجرای دو سند جدید](Doc/access-and-execution-matrix-fa.md):** دسترسی‌های لازم، قابلیت‌های پیاده‌شدهٔ رصد/گزارش/نشر و محدودیت‌های آزمون واقعی؛ دو دستورالعمل اصلی در `Doc/` بدون تغییر مانده‌اند.
7. **[طرح اولیهٔ API مستقیم](DIRECT_API_ACCESS_PLAN.md):** بررسی تاریخی امکان مشاهدهٔ فقط‌خواندنی، مربوط به پیش از تصحیح مالک و ساخت برنامهٔ مستقل.

منبع انتقال: ریپوی قدیمی [`bazino-advertising-campaign` در commit `f844616`](https://github.com/paymanshafayan/bazino-advertising-campaign/blob/f84461608163c1d2478501eecd9919b4488d50a0/HANDOFF.md) و قواعد مالک در `Doc/user-rules-fa.md` همان commit. داده‌های وضعیت محصول از **شاخهٔ مرجع پورتال** جدا خوانده می‌شوند. به‌جای کپی انبوهِ رسانه‌ها/رمزها/پل قدیمی، دانش قابل‌استفاده و پیوند پایدار به دارایی‌ها/منابع آمده است.

## ابزارهای کمپین

| ابزار | نقش |
|---|---|
| **Zernio — ستون اصلی** | انتشار و سنجش برای حساب‌های متصل Instagram، YouTube، Telegram و دیگر شبکه‌ها از **یک API** و `platform`/`accountId`؛ استودیوی Windows به شبکه‌ها مستقیم متصل نمی‌شود. اتصال واقعی حساب‌ها هنوز تأیید نشده است. |
| FLUX / Cloudflare Workers AI | به‌طور پیش‌فرض از پنل استودیوی محتوای پورتال با کلیدهای سمت سرور Vault؛ بدون ورود مجدد کلید در EXE. اجرای مستقیم محلی فقط با ورود اختیاری کلید روی Windows مالک، و تأیید هزینه است. |
| Kling MCP | سرور رسمی `https://kling.ai/mcp` با OAuth مرورگر Windows و `who_am_i` برای تشخیص حساب/مدل‌ها؛ ورود واقعی هنوز انجام نشده است. CLI منطقه‌ای نصب نمی‌شود. |
| گیت آنلاین | ثبت حداکثر ۳۰ HTTPS API/MCP دلخواه سازگار با کلید/Bearer یا OAuth برای MCP در Windows، و استخراج متن صفحات عمومی؛ relay رمزگذاری‌شده فقط اتصال‌های مورد تأیید مالک را می‌بیند. شبکهٔ خصوصی، redirect، محتوای نیازمند ورود و `stdio` پشتیبانی نمی‌شوند. [راهنمای کامل](desktop-app/README.md). |

اتصال مستقیم YouTube/Telegram و Manus از برنامهٔ Windows حذف شده است. منظور از پشتیبانی Zernio داشتن اتصال و مجوز همان حساب در Zernio است، نه دسترسی خودکار ایجنت به همهٔ حساب‌ها.

«کمپین تبلیغاتی» (یوتیوب، FLUX، تلگرام) و «کمپین همکاری در فروش اینستاگرام» دو جریان **جدا** با بعضی زیرساخت‌های مشترک از جمله Zernio هستند. برنامهٔ محتوا و انتشار هر کدام باید مستقل، منبع‌دار و مصوب باشد.

## مرجع و مرز دسترسی

- مرجع بررسی وضعیت پروژه، شاخهٔ `arena/01a089a9-bazino-gamenet-portal` است؛ پیش از هر گزارش/تصمیم، تازه‌ترین SHA آن و در صورت نیاز دادهٔ زنده را جدا بررسی کنید. شاخهٔ ثبت تغییرات این نشست فقط `arena/01a0d4ee-bazino-gamenet-portal` است.
- مالک خواست **برنامهٔ مستقل با امکانات کامل** بسازیم، سپس Electron را رد و ساخت Windows با **GitHub Actions** را مبنا کرد؛ Actions فقط برای *ساخت* بسته است، نه اجرای خودکار کمپین. workflowها دستی ساخته شدند اما هر دو هنگام آپلود artifact با محدودیت ذخیره‌سازی GitHub شکست خوردند. اتصال حساب‌های واقعی و اختیار انتشار/هزینه‌کرد هنوز اثبات/صادر نشده‌اند؛ کلیدهای پورتال سروری‌اند و هر کلید محلیِ اختیاری فقط روی Windows مالک وارد می‌شود. پل قدیمی `cdp-bus` محل نوشتن این شاخهٔ کاری نیست؛ [پل استودیو روی شاخهٔ مجاز](desktop-app/browser-link/README.md) تا زمان اجرای مالک، به مرورگر وصل نیست.
- آماده‌بودن کد یا سلامت عمومی وب‌هوک به معنی دسترسی ایجنت به حساب Zernio/Manus/Telegram یا مجوز انتشار نیست. کلید، توکن، سشن و کد ورود در Git یا چت ذخیره نمی‌شوند.
- انتشار، ارسال پیام، هزینه‌کرد اعتبار، تغییر تنظیمات زنده و تغییر کد محصول فقط با درخواست، دامنهٔ اختیار و تأیید مشخص خودشان انجام می‌شوند. دستور انتقال حاضر صرفاً مستندات این پوشه را پوشش می‌دهد.
