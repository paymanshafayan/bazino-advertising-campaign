# آوانگار ۲٫۱ — انتخاب تبدیل محلی یا ابری برای ویندوز

از **تنظیمات → روش تبدیل گفتار** بین **محلی · روی همین دستگاه** و **ابری · OpenAI** انتخاب کنید، سپس **ذخیرهٔ تنظیمات** را بزنید. حالت فعال در صفحهٔ ضبط نمایش داده می‌شود. هنگام ضبط/تبدیل نمی‌توان حالت را تغییر داد. در صورت خطا، هیچ تغییر خودکاری بین این دو روش رخ نمی‌دهد.

اعلان‌های کنار ساعت همچنان حذف‌اند؛ میان‌بر نگه‌داشتن **Ctrl + Win**، بازیابی محدود میکروفون، کلید رمز‌شده و صفحهٔ Log با کپی در هر دو حالت حفظ شده‌اند.

## حالت محلی و استفاده از مدل‌های قبلی

۱. روش تبدیل را **محلی** انتخاب کنید.
۲. مدل قبلی خود (**Base / Small / Medium**) را انتخاب کنید. برای استفاده از دانلود قبلی Small، Small را انتخاب کنید؛ دانلود Small جای مدل Medium را نمی‌گیرد.
۳. برنامه ابتدا **همان مسیر نسخه‌های قبلی** را بررسی می‌کند:

```text
%LOCALAPPDATA%\Avanegar\models
```

این مسیر در همان حساب ویندوز استفاده می‌شود؛ پوشه یا نسخهٔ جدید و جداگانه‌ای برای مدل‌ها ساخته نشده است. از **باز کردن پوشهٔ مدل‌های قبلی** یا Win+R با مسیر بالا به آن دسترسی دارید.

۴. اگر مدل کامل پیدا شود، عبارت **«مدل موجود است؛ دانلود دوباره لازم نیست»** و مسیر دقیق نمایش داده می‌شود. دکمهٔ **بررسی و آماده‌سازی مدل محلی** فقط آن را از دیسک بارگذاری می‌کند؛ برای مدل کامل موجود حتی درخواست بررسی نسخه در اینترنت هم فرستاده نمی‌شود.
۵. اگر مدل موجود نباشد یا فایل‌های اصلی ناقص باشند، با زدن آماده‌سازی، دریافت/تکمیل در **همین پوشه** انجام می‌شود. بعد از دریافت کامل، تبدیل همان مدل بدون اینترنت و بدون API key کار می‌کند. شروع اولین تبدیل بدون آماده‌سازی نیز همین بررسی را انجام می‌دهد.

دکمهٔ **بررسی دوبارهٔ مدل — بدون دانلود** فقط دیسک را بررسی می‌کند و به اینترنت وصل نمی‌شود.

### چه ساختارهایی شناخته می‌شوند؟

ساختار معمول دانلودهای قدیمی Hugging Face بدون جابه‌جایی شناخته می‌شود، مثلاً:

```text
%LOCALAPPDATA%\Avanegar\models\models--Systran--faster-whisper-small\snapshots\<revision>\model.bin
```

برنامه مدل کامل را در snapshotهای مدل انتخابی پیدا می‌کند؛ حتی اگر `refs/main` حذف شده یا به یک دانلود جدیدِ ناقص اشاره کند، snapshot کامل قبلی دوباره استفاده می‌شود. لینک‌های سالم فایل‌ها به blobهای کش نیز پشتیبانی می‌شوند. پوشه‌های export دستی با نام `models\small` یا `models\faster-whisper-small` نیز پذیرفته می‌شوند؛ منظور مدل **CTranslate2/faster-whisper** است، نه فایل `.pt` اصلی Whisper.

صرف وجود پوشه یا فایل `.incomplete` کافی نیست. وجود و غیرخالی بودن `model.bin`، `config.json`، `tokenizer.json` و فایل vocabulary و قالب JSON بررسی می‌شود. این بررسی، جای اعتبارسنجی کامل وزن‌های باینری را نمی‌گیرد؛ خرابی داخل وزن‌ها ممکن است فقط هنگام بارگذاری مشخص شود. در این حالت خطا نشان داده می‌شود، اما فایل قبلی بدون اجازه حذف و صدا به ابر فرستاده نمی‌شود.

| مدل محلی | دریافت اولیهٔ تقریبی | ملاحظه |
| --- | --- | --- |
| Base | ۱۵۰ مگابایت | سبک‌تر، معمولاً خطای فارسی بیشتر |
| Small | ۵۰۰ مگابایت | مصرف متوسط؛ همان مدل قبلی قابل استفاده است |
| Medium | ۱٫۵ گیگابایت | حافظه/زمان بیشتر؛ دقت برای هر صدایی تضمین‌شده نیست |

پردازش محلی با CPU و INT8 انجام می‌شود. صدا و واژه‌های راهنما در حالت محلی به هیچ سرویس ابری ارسال نمی‌شوند؛ فقط دریافت مدلِ موجودنبودن/ناقص بودن به Hugging Face نیاز دارد. مدل‌ها داخل بستهٔ EXE نیستند و به بستهٔ جدید کپی نمی‌شوند.

### ارتقا از نسخه‌های قبلی

- انتخاب مدل نسخه‌های ۱.x حفظ و به حالت محلی منتقل می‌شود.
- تنظیمات ذخیره‌شدهٔ نسخهٔ ۲٫۰ در حالت ابری باقی می‌مانند؛ برای محلی شدن خودتان روش را تغییر دهید.
- حالت صریح ذخیره‌شدهٔ ۲٫۱ در اجراهای بعدی حفظ می‌شود؛ نصب تازه به‌طور پیش‌فرض محلی است.
- **پوشهٔ models را حذف نکنید** اگر می‌خواهید دانلودهای قبلی دوباره استفاده شوند. توصیهٔ حذف مدل‌های بلااستفاده در راهنمای نسخهٔ فقط‌ابری ۲٫۰ دیگر برای استفادهٔ محلی مناسب نیست.

## حالت ابری و پیش‌نیاز سرویس

- اینترنت و دسترسی مجاز به سرویس OpenAI در منطقهٔ پشتیبانی‌شده؛
- کلید **OpenAI API** از حساب/پروژهٔ خودتان با دسترسی به تبدیل گفتار؛
- اعتبار/صورتحساب فعال API. **اشتراک ChatGPT جای اعتبار API نیست** و صرف اتصال اینترنت برای استفاده کافی نیست؛
- میکروفون و مجوز برنامه‌های دسکتاپ در Windows 10/11 x64.

این موارد فقط برای حالت **ابری** لازم‌اند؛ حالت محلی هیچ کلید API یا اعتبار ابری نمی‌خواهد. کلید را **در چت، GitHub یا Log نفرستید**. برنامه به کلید GitHub یا تغییر دسترسی Arena نیازی ندارد. مسیر سرویس ثابت و HTTPS است؛ مقصد دلخواه یا دور زدن محدودیت‌های امنیتی/منطقه‌ای تعبیه نشده است.

مستندات و سیاست‌ها:
- [راهنمای Audio Transcriptions](https://developers.openai.com/api/docs/guides/speech-to-text)
- [مدل GPT-4o Transcribe](https://developers.openai.com/api/docs/models/gpt-4o-transcribe)
- [قیمت‌گذاری API](https://developers.openai.com/api/docs/pricing)
- [کنترل‌ها و نگهداری دادهٔ API](https://platform.openai.com/docs/guides/your-data)

## راه‌اندازی نسخهٔ آماده

۱. نسخهٔ قبلی را از آیکن کنار ساعت → **خروج** ببندید؛ ضربدر پنجره کافی نیست.
۲. بستهٔ جدید را **کامل** استخراج کنید. `Avanegar.exe` و پوشهٔ `_internal` باید کنار هم باشند. نصب Python لازم نیست.
۳. وارد **تنظیمات** شوید، روش تبدیل را انتخاب کنید. برای محلی، مراحل بخش بالا را انجام دهید؛ برای ابری، کلید API را در کادر رمزدار وارد کنید.
۴. توضیح ارسال صدا و واژه‌های راهنما به OpenAI را بخوانید، گزینهٔ تأیید را روشن و **ذخیرهٔ تنظیمات** را بزنید.
۵. **آزمون اتصال ابری** را بزنید. این آزمون صدا نمی‌فرستد و دسترسی کلید به مدل را بررسی می‌کند؛ اعتبار/سهمیهٔ واقعی تبدیل در اولین درخواست صوتی مشخص می‌شود.
۶. میکروفون را انتخاب کنید؛ برای فارسی، زبان را روی **فارسی** بگذارید.

کلید با **Windows DPAPI** و وابسته به همین حساب ویندوز رمز می‌شود و زیر `%LOCALAPPDATA%\Avanegar\api-key.dpapi` قرار می‌گیرد. کلید وارد `settings.json` یا Log نمی‌شود. برای حفظ کلید فعلی، کادر را خالی بگذارید؛ برای عوض کردن، کلید جدید را وارد و ذخیره کنید. دکمهٔ **حذف کلید ذخیره‌شده** فایل را حذف می‌کند. انتقال این فایل به حساب/دستگاه دیگر روش انتقال کلید نیست. DPAPI از داده در حالت ذخیره‌شده حفاظت می‌کند؛ در برابر بدافزار اجراشده با دسترسی همان کاربر تضمین نمی‌دهد.

پس از ارتقا، مدل‌های محلی قدیمی **در همان پوشه قابل استفاده‌اند**؛ نیازی به جابه‌جایی یا دانلود دوبارهٔ مدل کامل نیست.

## استفادهٔ روزمره

1. در کادر متنی مقصد، مثلاً Word، مرورگر یا پیام‌رسان، کلیک کنید.
2. **Ctrl + Win** را با هم فشار دهید و **نگه دارید**. پس از آماده شدن میکروفون صحبت کنید.
3. کلیدها را **رها کنید**. رها شدن یکی از کلیدهای لازم، ضبط را متوقف می‌کند؛ فشار دوم لازم نیست.
4. تا پایان تبدیل در حالت انتخابی، پنجره و محل نشانگر را عوض نکنید. متن در کادر فعلی درج می‌شود؛ انتخاب متن ممکن است با نتیجه جایگزین شود.

هر ضبط تا ۵ دقیقه است. تبدیل پس از پایان ضبط انجام می‌شود، نه هم‌زمان کلمه‌به‌کلمه. دکمهٔ داخل برنامه با کلیک اول ضبط را شروع و با کلیک دوم تمام می‌کند و فقط متن داخلی تولید می‌کند. اگر پنجرهٔ مقصد عوض شده باشد، درج خودکار انجام نمی‌شود؛ متن از آوانگار قابل کپی است. بعضی بازی‌ها، پنجره‌های Administrator و صفحهٔ امن ویندوز paste را نمی‌پذیرند.

میان‌برهای جایگزین `Ctrl+Shift+Space` و `Ctrl+Alt+F9` هم حالت نگه‌داشتن/رهاکردن دارند. کلید سومِ نامرتبط در حرکت Ctrl+Win (مانند Ctrl+Win+D) ضبط آن حرکت را لغو می‌کند. همهٔ کلیدها را پیش از ضبط بعدی رها کنید.

## بازیابی خودکار خطاها

گزینهٔ **بازیابی خودکار میکروفون و تلاش با ورودی پیش‌فرض** به‌طور پیش‌فرض روشن است و قابل خاموش کردن است:

| وضعیت | رفتار برنامه |
| --- | --- |
| دستگاه انتخاب‌شده قطع شده یا خطای شناخته‌شدهٔ PortAudio هنگام باز کردن | پس از بستن امن، فهرست دستگاه‌ها را بازسازی می‌کند و **فقط یک بار** ورودی پیش‌فرض ویندوز را امتحان می‌کند. در صورت موفقیت، انتخاب به پیش‌فرض تغییر می‌کند. |
| کاربر وسط شناسایی دوباره کلیدها را رها کرده | دیگر ضبط تازه‌ای شروع نمی‌شود. |
| پس از ضبط هیچ سیگنال قابل استفاده‌ای ثبت نشده | **صدا به API ارسال نمی‌شود**؛ دستگاه‌ها دوباره شناسایی می‌شوند و داخل پنجره از شما خواسته می‌شود دوباره ضبط کنید. گفتار ازدست‌رفته قابل بازیابی نیست. |
| ضبط بسیار کوتاه/لغوشده | برای آن درخواست صوتی ساخته نمی‌شود؛ لغو، بازیابی میکروفون را هم آغاز نمی‌کند. |
| پاسخ ابری بدون متن | متن قبلی تکرار یا درج نمی‌شود؛ در صورت فعال بودن بازیابی، میکروفون‌ها برای ضبط بعدی بازخوانی می‌شوند. |
| timeout برقراری اتصال یا محدودیت موقت 429 با انتظار کوتاه | **یک تلاش مجدد**، حداکثر ۲ درخواست؛ مدت انتظار خودکار ۱ تا ۵ ثانیه است. |
| timeout هنگام خواندن پاسخ، قطع اتصال نامشخص یا خطای 5xx | ارسال مجدد خودکار انجام نمی‌شود؛ درخواست ممکن است قبلاً پردازش/محاسبه شده باشد و تکرار می‌تواند هزینهٔ مضاعف ایجاد کند. |
| کلید نامعتبر، اعتبار ناکافی، TLS نامعتبر، مجوز میکروفون خاموش | توضیح روشن داخل پنجره و Log؛ کلید، اعتبار و مجوز را خود کاربر باید اصلاح کند. بررسی گواهی TLS هرگز خاموش نمی‌شود. |
| گیر کردن واقعی درایور | رابط منتظر درایور نمی‌ماند؛ پس از حدود ۱۰ ثانیه وضعیت مشخص و stack فنی ثبت می‌شود. **باز کردن هم‌زمان/تکرار بی‌پایان روی درایور گیرکرده ممنوع است**؛ خروج کامل و بررسی سخت‌افزار لازم است. |

شناسایی/باز کردن/بستن میکروفون همگی روی یک کارگر جدا و به‌صورت سریالی هستند. ضبط جدید هنگام بازیابی یا تبدیل غیرفعال است. درایور خراب، نبود سخت‌افزار یا سیاست سازمانی را نمی‌توان با نرم‌افزار تضمینی اصلاح کرد. در حالت سکوتِ واقعی نیز ممکن است برنامه درخواست ضبط دوباره بدهد؛ وجود سیگنال لزوماً به معنی وجود گفتار واضح نیست.

## واژه‌های ویژهٔ فارسی

نام محصول/شرکت را با ویرگول در کادر واژه‌ها وارد کنید. پیش‌فرض «آوانگار» است؛ برای خاموش کردن کادر را خالی کنید. حداکثر ۳۰۰ نویسه است، فقط در زبان فارسی اعمال می‌شود: در حالت **محلی** صرفاً روی دستگاه استفاده و در حالت **ابری** همراه صدا به سرویس ارسال می‌شود. واژه‌ها در تنظیمات محلی ذخیره می‌شوند، اما در Log ثبت نمی‌شوند. این راهنمای املایی است، نه آموزش مدل و نه جایگزینی جمله با پاسخ ازپیش‌نوشته‌شده. متن، نام‌ها و اعداد را پیش از ارسال بازبینی کنید؛ دقت تضمین نمی‌شود.

## مجوز میکروفون

**Windows 11:** Settings → Privacy & security → Microphone. گزینه‌های **Microphone access**، **Let apps access your microphone** و پایین صفحه **Let desktop apps access your microphone** را روشن کنید.

**Windows 10:** Settings → Privacy → Microphone. زیر **Allow access to the microphone on this device** روی **Change** بزنید و دسترسی را روشن کنید. سپس **Allow apps to access your microphone** و **Allow desktop apps to access your microphone** را روشن کنید.

میان‌بر مستقیم: Win+R → `ms-settings:privacy-microphone` → Enter.

برای آوانگار، مجوز مشترک **desktop apps** مهم است؛ لازم نیست نام آن در فهرست برنامه‌های Store دیده شود و معمولاً کلید اختصاصی هر برنامهٔ دسکتاپ وجود ندارد. پس از تغییر مجوز، برنامه را کامل ببندید و دوباره اجرا کنید. در Settings → System → Sound → Input، ورودی را آزمایش کنید. کلید قطع صدای هدست را بررسی کنید. گزینه‌های خاکستری/Managed by your organization نیازمند بررسی مدیر دستگاه هستند؛ اجرای خود برنامه با Administrator راه‌حل مجوز نیست.

## اعلان‌ها و Log

برنامه هیچ toast، پیام بالونی یا صدای اعلان برای شروع/پایان/خطا نمی‌فرستد. آیکن کنار ساعت فقط برای باز کردن پنجره و خروج باقی می‌ماند. نشانگر حریم خصوصی میکروفون که خود ویندوز نمایش می‌دهد، متعلق به سیستم‌عامل است و برنامه آن را خاموش نمی‌کند.

از صفحهٔ **گزارش خطا / Log → کپی لاگ** برای گزارش مشکل استفاده کنید. لاگ حاوی نسخه، مرحله، نوع خطا و کد HTTP است؛ **صدا، متن گفتار، واژه‌ها، بدنهٔ پاسخ سرویس و کلید API ثبت نمی‌شوند**. قبل از اشتراک‌گذاری بازبینی کنید. حداکثر ۱۰۰۰ خط در صفحه و سه فایل چرخشی تقریباً یک‌مگابایتی در `%LOCALAPPDATA%\Avanegar\logs` نگهداری می‌شوند. انتهای نشست قبلی بعد از باز کردن برنامه قابل مشاهده است.

## حریم خصوصی و حذف داده

- فایل صوتی روی دیسک این برنامه نوشته نمی‌شود. در حالت **محلی** صدا و راهنمای واژه‌ها فقط روی دستگاه پردازش می‌شوند و مدل کامل موجود آفلاین کار می‌کند. در حالت **ابری** ضبط به OpenAI ارسال می‌شود و نگهداری داده در سرور تابع سیاست و تنظیمات حساب سرویس است.
- متن پاسخ در حافظه/۱۰ گفتار اخیر است؛ ذخیرهٔ متن توسط کاربر فایل دائمی می‌سازد.
- کپی یا درج خودکار کلیپ‌بورد قبلی را جایگزین می‌کند. تاریخچهٔ Win+V و همگام‌سازی ویندوز ممکن است آن را نگه دارند؛ پاک کردن داخل برنامه، آن‌ها را پاک نمی‌کند.
- برای حذف داده‌های محلی، ابتدا از برنامه کامل خارج شوید و پوشهٔ `%LOCALAPPDATA%\Avanegar` را حذف کنید. فایل‌های صادرشده و داده‌های احتمالی سرویس جدا هستند.

## اجرا از کد و ساخت EXE

برای توسعه/ساخت: Python **3.11 x64** همراه Launcher روی Windows 10/11 x64.

- اجرای کد: `run-windows.bat`
- ساخت: `build-windows.bat`
- خروجی: `dist\Avanegar\Avanegar.exe`؛ **کل پوشه** را منتقل کنید. سیستم مقصد Python لازم ندارد.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m avanegar
```

Workflow موجود `.github/workflows/avanegar-windows.yml` بدون نیاز به تغییر دسترسی، با push کد برنامه اجرا می‌شود و artifact با نام **Avanegar-Windows-x64** می‌سازد. الگوی آن نیز زیر `avanegar/workflows/` موجود است. بسته امضای دیجیتال ندارد.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

تست‌های شبکه و استنتاج شبیه‌سازی‌شده‌اند و بررسی کش با فایل‌های آزمایشی انجام می‌شود: **از کلید واقعی استفاده نمی‌کنند، فایل صوتی واقعی آپلود نمی‌کنند و هزینهٔ API ایجاد نمی‌کنند.** ساخت موفق، جای تست روی میکروفون و حساب ابری خودتان را نمی‌گیرد.
