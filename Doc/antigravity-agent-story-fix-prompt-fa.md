# پرامپت آمادهٔ ایجنت آنتی‌گراویتی — اصلاح فوری انتشار استوری (عنوان برنامه: استودیوی بازینو / ژینوس)

> این متن را عیناً به ایجنت بدهید. دامنه **فقط همین یک ایراد** است؛ کار رابط کاربری تازه و کار لوگو دست نخورد.

---

## دستور مالک (۲۰۲۶-۱۰-۰۴)

در برنامهٔ ویندوزی ژینوس یک ایراد واقعی پیدا شده که امشب روی پیج بازینو اثر گذاشت: **استوری به‌جای «استوری»، به‌صورت «پست فید» منتشر می‌شود.** این کار همان تغییر کوچک است؛ **فقط همین را انجام بده** و کار رابط کاربری تازه را متوقف نکن.

### ۱) شاهد واقعی (ثبت‌شده)
- استوری اول امشب ساعت ۱۸:۰۰ به وقت قبرس از صف تأییدشده منتشر شد؛ برنامه درخواست را فرستاد و ۱۰ ثانیه بعد رکورد «ناموفق» نوشت («زرنیو موفقیت نهایی Instagram را تأیید نکرد»)، ولی تصویر **واقعاً روی فید پیج نشست**.
- مسیر کد: `استودیوی تبلیغات و بازاریابی/marketing-app/src/BazinoMarketing.Core/Publishing/PublishQueueModels.cs` → کلاس `ZernioPublishBuilder` → متد `BuildInstagramPost`.
- ایراد: برای `Kind == "story"` فقط `locationId` و `content` (کپشن) حذف می‌شوند و **هیچ پرچم استوری به زرنیو نمی‌رود**؛ پس زرنیو تصویر را پست فید معمولی می‌سازد.

### ۲) قرارداد رسمی زرنیو (منبع: docs.zernio.com/platforms/instagram)
انتشار استوری فقط با این پرچم انجام می‌شود و نبودش یعنی «پست فید»:

```json
{ "platform": "instagram", "accountId": "...", "platformSpecificData": { "contentType": "story" } }
```

### ۳) تغییر خواسته‌شده (حداقلی و بسته)
1. در `BuildInstagramPost`، برای محتوای استوری این را اضافه کن:
   `platform["platformSpecificData"] = new JsonObject { ["contentType"] = "story" };`
2. استثنای ثبت‌شدهٔ مالک برای استوری حفظ شود: **بدون `locationId`** و **بدون کپشن** (`content`).
3. رفتار بقیهٔ قالب‌ها (post / carousel / reel) **صفر تغییر** — نه بدنه، نه لوکیشن، نه کپشن.
4. هیچ تغییری در مدل صف، اعتبارسنجی، پوشه‌های `ready/approved/published/failed`، رسانه‌ها یا رابط کاربری نده.
5. هیچ انتشار واقعی، ساخت نسخه یا ریلیز انجام نده مگر با اجازهٔ صریح مالک.

### ۴) آزمون الزامی (رگرسیون)
در `tests/BazinoMarketing.Core.Tests/PublishQueueTests.cs` یک تست تازه اضافه کن:
- بدنهٔ **استوری**: باید `platformSpecificData.contentType == "story"` داشته باشد و نه `locationId` و نه `content`.
- بدنهٔ **post / carousel / reel**: نباید `contentType = "story"` داشته باشد (رفتار امروز دست‌نخورده).
- آزمون‌های فعلی باید سبز بمانند.

### ۵) شواهدی که باید در گزارش برگردانی
- خلاصهٔ تفاوت (فایل‌ها و چند خط تغییر) + **هش کامل کامیت**.
- خروجی آزمون‌های core (سبز/سرخ).
- اگر ساخت انجام دادی: شمارهٔ `marketing-app-dev-NN` و SHA-256 فایل اجرایی (فقط با اجازهٔ مالک).
- تأیید صریح اینکه پیکربندی و پروندهٔ صف و رسانه‌ها دست نخورده‌اند.

### ۶) قواعد کار (الزامی)
- فقط روی شاخهٔ خودت کار کن؛ هیچ force-push، هیچ بازنویسی تاریخ، هیچ `git add -A`.
- رازها (کلید زرنیو، توکن پورتال، اثر انگشت ایجنت) هرگز در کد، صف، گزارش یا لاگ ننویس.
- یک کامیت با پیام روشن و تک‌موضوعی (مثال: `fix(publish): send platformSpecificData.contentType=story for stories (owner 2026-10-04)`). اگر خط تولید با `[build]` کار می‌کند و مالک اجازه داد، همان را در پیام بیاور.
- **همگام‌سازی دو مخزن:** کد برنامه در دو مخزن کپی دارد. تغییر را در کپی خودت بزن و در گزارش **فهرست دقیق فایل‌ها و هش کامیت** را بده تا کپی دیگر (مخزن پورتال، شاخهٔ `arena/01a10048-bazino-gamenet-portal`) عیناً هم‌سان شود؛ اگر دسترسی نوشتن به آن مخزن داری، خودت هم‌سان کن و صریح بنویس.
- **شمارهٔ نسخه:** در مخزن `<Version>` روی `0.8.4` است ولی برنامهٔ نصب‌شده `0.8.5` گزارش می‌کند؛ اگر نسخه را بالا می‌بری، این ناهم‌خوانی را در گزارش توضیح بده و شمارهٔ تازه را با واقعیت یکدست کن. نسخه‌های قدیمی را دوباره نصب نکن.
- **خارج از دامنه:** کار لوگوی رسمی روی محتوا (قانون ۸٫۳ راهنمای تولید) و رابط کاربری تازهٔ تو — هیچ‌کدام در این کار نیستند.

### ۷) معیار پذیرش
پس از این تغییر، هر استوری باید در بخش استوری اینستاگرام منتشر شود (نه فید) و پاسخ زرنیو وضعیت `published` بدهد؛ تست رگرسیون این را تضمین کند و هیچ قالبی جز استوری تغییر رفتاری نداشته باشد.
