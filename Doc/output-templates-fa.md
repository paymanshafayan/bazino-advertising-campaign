# 📐 قالب‌های خروجی

**هدف:** به‌جای بازآفرینی شکل خروجی هر بار، از اینجا کپی می‌شود.

تحقیق نشان می‌دهد **مثال از قاعده قوی‌تر است** — یک نمونه ورودی/خروجی مشخص،
فشار بافت طولانی را بهتر از یک قاعده اعلامی تحمل می‌کند. این سند مجموعه همان
مثال‌هاست.

---

# ۱. پرامپت ویدئو

## قاعده طلایی

**یک پرامپت در هر پاسخ. یک بلوک یکپارچه. ترجمه کامل. بعد توقف.**

## قالب

````markdown
# 🎬 پرامپت N از M — [عنوان]

```text
[بلوک کامل و یکپارچه — همه چیز داخلش:
 فرمت · محیط · آدم‌ها · محتوای صفحه · شات‌لیست ·
 صدا · متن روی تصویر (هر دو زبان) · گرید · فریم پایانی · محدودیت‌ها]
```

---

# 📖 ترجمه فارسی پرامپت بالا

[ترجمه **کل** بلوک، بخش‌به‌بخش، به فارسی روان]

---

## فایل‌هایی که به Flow می‌دهید

| نقش | فایل |
|---|---|
| تصویر مرجع محیط | `Assets/club/club-tall-02.jpeg` |

تأیید می‌کنید تا ذخیره کنم و بروم سراغ پرامپت N+1؟
````

## ⚠️ سه شکست ثبت‌شده

| شکست | چرا غلط است |
|---|---|
| سه پرامپت در یک پاسخ | مالک نمی‌تواند تک‌تک تأیید کند |
| «پرامپت مشترک» + «اختصاصی» + «متن‌ها» جدا | در Flow قابل استفاده نیست |
| فقط متن روی تصویر ترجمه شد | مالک می‌خواهد **کل** پرامپت را بفهمد |

## دو زبان در یک پرامپت

هر دو نسخه **داخل همان بلوک**، نه در پیام جدا:

```text
ON-SCREEN TEXT
[مشخصات فونت، موقعیت، زمان‌بندی — یک بار]

  VERSION A — TURKISH:
  [متن ترکی]

  VERSION B — PERSIAN:
  [متن فارسی]

  For Version B use a typeface with full Persian script support and
  right-to-left direction. Keep position, size, timing, colour and line
  count identical to Version A.
```

# ۲. پرامپت ایجنت پورتال

````markdown
# پرامپت ایجنت پورتال — [موضوع]

**نسخه:** N · **تاریخ:** YYYY-MM-DD
**مقصد:** ایجنت ریپوی `bazino-gamenet-portal`، برنچ `arena/...`
**مبنای بررسی:** بازرسی مستقیم کد در YYYY-MM-DD — شماره‌خط‌ها تأیید شده‌اند

> ⚠️ این برنچ مستقیماً روی Railway دیپلوی می‌شود. هر push یعنی production.

## ۰. چرا این کار لازم است
[پیامد واقعی، نه توصیف فنی]

## ۱. مقادیر صحیح — مرجع واحد
| فیلد | ❌ غلط فعلی | ✅ صحیح |

## ۲ تا N. بچ‌ها با شماره‌خط دقیق

## بررسی پس از اجرا
```bash
grep -rn "..." --include=*.ts . | grep -v node_modules
npm run build && npm test
```

## گزارش برگشتی
[فهرست دقیق آنچه باید گزارش شود]

## ترتیب اجرا
````

**قاعده:** همیشه اول کد را **مستقیماً بازرسی کن**، نه فهرست HANDOFF.
یک بار فهرست ۴ فایل داشت، واقعیت ۶ فایل بود.

# ۳. ورک‌فلو گیت‌هاب

ایجنت **نمی‌تواند** فایل ورک‌فلو را push کند — توکنش `workflows` scope ندارد.

````markdown
# 🔧 ورک‌فلو — فایل کامل برای جایگزینی

**نام فایل:** `.github/workflows/[name].yml`
**مسیر:** گیت‌هاب → فایل → Edit → همه را پاک کنید → پیست → Commit

```yaml
[فایل کامل — هرگز فقط یک بخش]
```

## چه چیزی عوض شد
| تغییر | چرا |
````

⚠️ **هرگز فقط یک مرحله را نده.** مالک صریح گفت فایل کامل بگذار.

---

# ۴. گزارش پایان کار

بعد از اجرای بی‌وقفه یک پلن (قانون ۱):

````markdown
# 📋 گزارش

**ساخته شد:** [یک خط]
**تست شد:** [نتیجه واقعی، نه ادعا]
**کار شما:** [گام بعدی مالک]

⚠️ [هر چیزی که تست نشده یا نامطمئن است]
````

**حداکثر چند خط.** جزئیات را مالک می‌پرسد.

---

# ۵. وقتی چیزی شکست خورد

````markdown
## 🔴 [عنوان مشکل]

**نشانه:** [آنچه دیده شد]
**علت:** [ریشه واقعی، نه حدس]
**رفع:** [آنچه انجام شد]

[یا اگر حل نشد:]
**دو بار تلاش شد و نشد.** برای ادامه لازم است شما [کار مشخص] را انجام دهید.
````

**هرگز تلاش بی‌پایان.** بعد از ۲-۳ بار، اعلام کن و رد شو.

---

# ۶. وقتی مالک پیش‌نویس می‌دهد

پیش‌نویس مالک **هرگز دور ریخته نمی‌شود**.

````markdown
## بررسی پیش‌نویس شما

**آنچه قوی‌تر از مال من بود:**
| مورد | چرا نگه داشتم |

**آنچه اصلاح کردم:**
| مورد | دلیل |

[نسخه نهایی]
````

دو بار پیش‌نویس مالک چیزی داشت که مال ایجنت نداشت — نقطه قطع روی باز شدن در،
و متن ثابت بالای کادر.

---

# ۷. ارائه گزینه‌ها

وقتی چند راه هست و تصمیم با مالک است:

````markdown
| گزینه | مزیت | هزینه |
|---|---|---|
| الف | ... | ... |
| ب ⭐ | ... | ... |

**پیشنهاد من: ب** — [یک جمله دلیل]

کدام؟
````

⭐ روی پیشنهاد، ولی **تصمیم با مالک**. قانون ۰.

---

# قواعد مشترک همه قالب‌ها

| قاعده | جزئیات |
|---|---|
| زبان | فارسی · پیام خطای فنی انگلیسی بماند |
| صداقت | تست‌نشده = صریح بگو تست‌نشده |
| یک قلم | یک خروجی در هر پاسخ، بعد توقف |
| آماده کپی | بلوک کامل، نه تکه‌تکه |
| بدون حدس | عدد/تاریخ/قیمت تأییدنشده ننویس |

---

# ✅ چک‌لیست این سند

**قبل از تحویل هر خروجی:**
```
□ قالب مناسب را از این سند پیدا کردم؟
□ خروجی یک بلوک کامل است، نه تکه‌تکه؟
□ فقط یک قلم تحویل می‌دهم؟
□ اگر پرامپت ویدئو است، ترجمه کامل دارد؟
□ اگر ورک‌فلو است، فایل کامل است نه یک بخش؟
□ در انتها توقف و انتظار تأیید گذاشته‌ام؟
```
