# طرح کامل کمپین تبلیغاتی روزانه Telegram بازینو پرو

**وضعیت:** سند اجرایی کمپین

**معماری:** Manus → Bazino Portal API → Railway Telegram Gateway → Telegram User Account

**محدوده:** کمپین‌های محلی بازینو پرو در İskele، Long Beach و شمال قبرس، با مقصدهای Telegram که عضویت و مجوز آن‌ها به‌صورت پویا و واقعی احراز شده است.

---

## ۱. هدف و خروجی روزانه

هدف کمپین، معرفی شفاف و مرتبط Bazino Pro به مخاطبانی است که در گفت‌وگوهای عمومی دربارهٔ بازی، کنسول، سرگرمی، دورهمی یا فعالیت آخر هفته صحبت می‌کنند. لحن پیام باید کوتاه، دوستانه و متناسب با زبان همان گفت‌وگو باشد؛ اما هویت تجاری بازینو هرگز پنهان نشود.

در هر اجرای روزانه، سه بخش بررسی می‌شود:

1. پیش‌نویس کمپین Telegram Bazino Pro؛
2. گزارش عملکرد روزانهٔ Affiliate Marketing؛
3. بررسی Reelهای منتشرشده در Instagram رسمی Bazino طی ۲۴ ساعت گذشته و آماده‌سازی cross-post برای کانال رسمی Telegram، فقط در صورت وجود approval معتبر.

هیچ پیام، draft، approval یا cross-postی بدون رعایت گیت‌های این سند ارسال نمی‌شود.

## ۲. تقسیم مسئولیت‌ها

| جزء | مسئولیت‌های مجاز | مسئولیت‌های خارج از دامنه |
|---|---|---|
| **Manus** | بررسی health، دریافت مقصدهای مجاز، جست‌وجوی context عمومی، انتخاب مقصد، تولید متن محلی، اعمال سیاست، ساخت draft، محاسبه hash و تفسیر گزارش | نگهداری مستقیم session کاربری Telegram، دورزدن پورتال یا ارسال مستقیم خارج از مسیر رسمی |
| **Bazino Portal** | ثبت draft، مقصد، context، approval، hash، affiliate، idempotency، audit، وضعیت تحویل و گزارش روزانه | انتخاب مستقل مقصد یا تولید مستقل متن بدون تصمیم Manus |
| **Railway Telegram Gateway** | نگهداری session مجاز، عملیات authenticated read، بررسی permission و اجرای send command معتبر و منقضی‌نشدهٔ پورتال | انتخاب مقصد، تولید متن، زمان‌بندی مستقل، join، invite، mention انبوه، DM یا ارسال bulk |
| **Instagram Connector** | خواندن feed رسمی، دریافت Reelهای اخیر، permalink، caption، timestamp و media reference | انتشار یا تغییر محتوای Instagram بدون approval مربوط |

Railway فقط مجری فنی دستور امضاشده و معتبر پورتال است و بدون آن حق ارسال ندارد.

## ۳. گیت سلامت پیش از هر اجرا

ابتدا باید درخواست زیر اجرا شود:

```http
GET https://bazino.pro/api/manus/health
```

پاسخ سالم نمونه:

```json
{
  "ok": true,
  "service": "bazino-portal",
  "telegram_gateway": "reachable"
}
```

اگر `telegram_gateway` برابر `unreachable` یا `session_not_configured` بود:

- اجرای کمپین Telegram متوقف شود؛
- هیچ مقصد، draft یا ارسال جدیدی انجام نشود؛
- وضعیت خطا و timestamp ثبت شود؛
- بررسی Reel فقط به‌صورت read-only ادامه یابد، اما cross-post انجام نشود؛
- علت در گزارش روزانه اعلام شود.

توکن‌ها، sessionها، API hash و secretها نباید در خروجی، log یا گزارش نمایش داده شوند.

## ۴. انتخاب پویای مقصدها

از فهرست ثابت کانال‌ها و گروه‌های پروژه استفاده نشود. مقصدها فقط از پاسخ واقعی پورتال انتخاب شوند:

```http
GET /api/manus/telegram/dialogs?member_only=true&sendable_only=true
```

هر مقصد پیشنهادی باید همهٔ شروط زیر را داشته باشد:

- حساب کاربری یا ربات بازینو واقعاً عضو مقصد باشد؛
- مجوز فعال ارسال پیام وجود داشته باشد؛
- شناسهٔ دقیق مقصد مشخص باشد؛
- نوع مقصد channel یا group/supergroup عمومی باشد؛
- مقصد دایرکت، private chat یا گفت‌وگوی خصوصی نباشد؛
- قوانین مقصد و امکان تبلیغات بررسی شده باشد؛
- context عمومی مرتبط در پیام‌های اخیر پیدا شده باشد؛
- مقصد قبلاً برای همین کمپین استفاده نشده باشد؛
- مقصد در سقف روزانهٔ یک تا دو مقصد قرار گیرد.

اگر هر شرط نامشخص باشد، مقصد رد شود. اگر مقصد یا context مناسب وجود نداشت، دقیقاً این وضعیت ثبت شود:

> مقصد قابل‌انتشار یافت نشد

در این حالت هیچ پیام یا draft انتشارمحوری ساخته یا ارسال نشود.

### بررسی مجوز مقصد

برای مقصد انتخاب‌شده:

```http
GET /api/manus/telegram/dialogs/{dialog_id}/permissions
```

فقط زمانی مقصد قابل استفاده است که `is_member=true` و `can_send=true` باشد. برای cross-post و رسانه باید `can_send_media=true` نیز تأیید شود.

## ۵. جست‌وجوی context عمومی مرتبط

جست‌وجو فقط در پیام‌های عمومی اخیر و در مقصدهایی انجام شود که بازینو مجاز به دسترسی به آن‌هاست:

```http
GET /api/manus/telegram/dialogs/{dialog_id}/messages/search?keywords=gaming,PS5,Xbox,console,game%20night,weekend,bored,entertainment,بازی,پلی‌استیشن,تفریح,آخر%20هفته,oyun,PlayStation,eğlence,игра,развлечения&lookback_hours=72&limit=20
```

کلیدواژه‌های اصلی:

- انگلیسی: `gaming`, `PS5`, `Xbox`, `console`, `game night`, `weekend`, `bored`, `entertainment`؛
- فارسی: `بازی`، `پلی‌استیشن`، `تفریح`، `آخر هفته`؛
- ترکی: `oyun`، `PlayStation`، `eğlence`؛
- روسی: `игра`، `развлечения`.

اولویت فقط بر اساس موضوع عمومی گفت‌وگو تعیین شود؛ از شماره تلفن، پروندهٔ شخصی، مشخصات حساس، تحلیل شخصیت یا فهرست‌سازی فردی استفاده نشود.

اولویت با گفت‌وگوهایی است که در آن‌ها دربارهٔ محل بازی، سرگرمی آخر هفته، دورهمی کنسولی، مسابقه یا تجربهٔ gaming lounge سؤال عمومی مطرح شده است. اگر context مرتبط پیدا نشد، تبلیغ تزریقی انجام نشود.

## ۷. ساخت و ثبت draft

برای هر مقصد واجد شرایط، draft باید شامل این موارد باشد:

- شناسهٔ دقیق مقصد؛
- عنوان یا username عمومی مقصد؛
- نوع مقصد و وضعیت عضویت؛
- وضعیت permission؛
- شناسهٔ پیام context؛
- زبان پیام؛
- متن دقیق نهایی؛
- CTA و لینک سایت؛
- disclosure؛
- affiliate code و affiliate URL، در صورت وجود؛
- media metadata، در صورت وجود؛
- hash متن و metadata؛
- request ID و idempotency key؛
- تاریخ انقضای approval؛
- پرچم `requires_approval=true`.

مسیر ثبت draft در قرارداد پورتال:

```http
POST /api/manus/campaign/drafts
```

نمونهٔ مفهومی:

```json
{
  "request_id": "manus-campaign-YYYY-MM-DD-001",
  "campaign": "telegram-local-gaming",
  "dialog_id": "EXACT_DIALOG_ID",
  "language": "fa",
  "context_message_id": "CONTEXT_MESSAGE_ID",
  "message": "FINAL_EXACT_MESSAGE",
  "cta_url": "https://bazino.pro",
  "affiliate_code": "OFFICIAL_CODE_IF_AVAILABLE",
  "affiliate_url": "OFFICIAL_URL_IF_AVAILABLE",
  "disclosure": "این معرفی با همکاری بازینو پرو انجام می‌شود.",
  "media_metadata": {},
  "requires_approval": true
}
```

این نمونه فقط قرارداد داده است؛ بدون مقصد و context واقعی نباید با مقادیر ساختگی ثبت شود.

## ۸. کنترل hash و approval

پیش از approval و دوباره بلافاصله پیش از ارسال، hash محتوای دقیق محاسبه و ثبت شود. ورودی hash باید شامل همهٔ موارد زیر باشد:

- متن پیام؛
- CTA؛
- disclosure؛
- لینک یا کد affiliate؛
- قالب‌بندی؛
- media metadata؛
- مقصد دقیق.

هر تغییر حتی یک کاراکتر باعث تغییر hash می‌شود و approval قبلی را باطل می‌کند. در این حالت draft جدید و approval جدید لازم است.

Approval باید:

- برای همان متن دقیق باشد؛
- برای همان مقصد دقیق باشد؛
- تاریخ انقضا داشته باشد؛
- پیش‌فرض حداکثر ۳۰ روز اعتبار داشته باشد؛
- پس از انقضا دوباره بررسی و تأیید شود؛
- بدون approval معتبر به Railway ارسال نشود.

وضعیت draft با مسیر read-only قابل بررسی است:

```http
GET /api/manus/campaign/drafts?limit=50
GET /api/manus/campaign/drafts/{draft_id}
GET /api/manus/campaign/decisions
```

## ۹. دستور ارسال و اجرای Gateway

فقط Portal می‌تواند دستور امضاشده و معتبر به Railway بدهد. دستور باید دارای این موارد باشد:

- `request_id`؛
- `draft_id`؛
- `dialog_id`؛
- متن دقیق تأییدشده؛
- hash یا `idempotency_key`؛
- `expires_at`؛
- امضای معتبر پورتال.

نمونهٔ مفهومی:

```json
{
  "request_id": "manus-campaign-YYYY-MM-DD-001",
  "draft_id": "APPROVED_DRAFT_ID",
  "dialog_id": "EXACT_DIALOG_ID",
  "message": "EXACT_APPROVED_MESSAGE",
  "idempotency_key": "sha256:EXACT_CONTENT_HASH",
  "expires_at": "ISO-8601"
}
```

Railway پیش از ارسال باید دوباره موارد زیر را بررسی کند:

- عضویت؛
- مجوز ارسال؛
- نوع غیرخصوصی مقصد؛
- انقضا؛
- تکراری‌نبودن؛
- سقف و فاصلهٔ ارسال؛
- تطابق hash متن با approval.

## ۱۰. توقف اضطراری و خطاها

با اولین `FloodWaitError` یا هر خطای permission:

1. کل کمپین pause شود؛
2. ارسال مقصدهای باقی‌مانده متوقف شود؛
3. timestamp، مقصد، request ID، کد خطا و وضعیت کمپین ثبت شود؛
4. retry تهاجمی انجام نشود؛
5. IP rotation، چند session، join خودکار، invite، mention انبوه و DM ممنوع بماند؛
6. ادامه فقط پس از بررسی انسانی و رفع علت مجاز باشد.

رفتار خطاهای پورتال:

| وضعیت | رفتار |
|---|---|
| `401` | توکن نامعتبر/منقضی یا احراز هویت ناقص؛ retry نکن و علت را گزارش کن |
| `403` | مجوز endpoint یا مقصد کافی نیست؛ ارسال نکن |
| `503` | Gateway یا session در دسترس نیست؛ اجرا را متوقف کن |
| `FloodWaitError` | کل کمپین pause و نیازمند بررسی انسانی |
| `permission error` | کل کمپین pause و نیازمند بررسی انسانی |
| مقصد یا context نامشخص | مقصد رد و «مقصد قابل‌انتشار یافت نشد» ثبت شود |

گزارش باید جداگانه و فقط بر اساس دادهٔ واقعی پورتال ارائه شود:

- کلیک؛
- لید؛
- رزرو؛
- پرداخت؛
- حضور؛
- کمیسیون در انتظار؛
- کمیسیون تأییدشده؛
- برگشت یا لغو؛
- پرداخت‌شده؛
- همکار برتر؛

مسیر گزارش:

```http

```

اگر داده در دسترس نبود، مقدار زیر گزارش شود:

```text
data_unavailable
```

یا:

> داده‌ای ثبت نشده/دسترسی موجود نیست

عدد صفر، conversion، commission یا partner برتر نباید حدس زده یا جعل شود. اطلاعات شخصی مشتریان، شماره تلفن و شناسهٔ حساس نمایش داده نشود.

## ۱۲. بررسی Reelهای Instagram و cross-post

در هر اجرای روزانه:

1. feed رسمی Instagram Bazino خوانده شود؛
2. فقط Reelهای منتشرشده در ۲۴ ساعت گذشته نگه داشته شوند؛
3. Reelهای تکراری با permalink، media ID یا شناسهٔ رسانه حذف شوند؛
4. برای هر Reel واجد شرایط این موارد ثبت شود: عنوان، permalink، زمان انتشار، media URL یا media ID و caption؛
5. caption همان Reel و media همان Reel برای cross-post آماده شود؛
6. approval معتبر برای همان Reel، همان caption، همان media و مقصد `@bazino_pro` بررسی شود؛
7. مجوز ارسال ویدیو برای کانال رسمی تأیید شود؛
8. فقط در صورت تطابق کامل approval و hash، ارسال از مسیر رسمی انجام شود؛
9. در غیر این صورت فقط draft/گزارش آماده شود و ارسال نشود.

هیچ Reel قدیمی‌تر از ۲۴ ساعت یا Reel تکراری cross-post نشود.

برای cross-post باید media URL معتبر یا فایل محلی قابل‌ارسال وجود داشته باشد. موفقیت فقط زمانی ثبت شود که API پاسخ `ok: true` و message ID بدهد.

## ۱۵. اصل نهایی

Manus مسئول بررسی context، انتخاب مقصد، تولید متن، اعمال سیاست و تفسیر گزارش است. Bazino Portal مسئول draft، approval، audit و وضعیت ارسال است. Railway فقط executor فنی دستور معتبر پورتال است. هیچ سرویس یا عاملی نباید مقصد خارج از عضویت واقعی، پیام خصوصی، ارسال بدون approval، اطلاعات ساختگی یا جزئیات تأییدنشده دربارهٔ قیمت، جایزه، قوانین یا تخفیف را وارد کمپین کند.
