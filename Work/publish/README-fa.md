# انتشار محتوا از طریق ورک‌فلو — راهنمای مالک

**تاریخ:** ۲۰۲۶-۰۹-۲۸
**هدف:** محتوای تأییدشده را بدون دست کردن به گوشی، از طریق ورک‌فلو منتشر کنی.

---

## ۱. این چطور کار می‌کند

```
۱. یک پوشهٔ محتوا می‌سازی        → Work/publish/<تاریخ>-<نام>/
۲. داخلش publish.json می‌گذاری   → تأیید، متن، رسانه، حساب‌ها
۳. ورک‌فلو را دستی اجرا می‌کنی   → گیت‌هاب → Actions → Publish approved content → Run
۴. اول با dry_run=true           → فقط نشان می‌دهد چه می‌فرستد، ничего منتشر نمی‌شود
۵. بعد با dry_run=false          → واقعاً منتشر می‌شود
```

**هیچ‌وقت خودش اجرا نمی‌شود.** ورک‌فلو فقط `workflow_dispatch` دارد؛ نه با push اجرا
می‌شود، نه زمان‌بندی دارد. یعنی محتوا فقط وقتی منتشر می‌شود که خودت دکمه را بزنی.

---

## ۲. یک بار برای همیشه: سه کار

### الف) فایل ورک‌فلو را بساز

من اجازهٔ ساختن فایل ورک‌فلو ندارم (محدودیت امنیتی گیت‌هاب برای کلید ایجنت). یک بار
خودت می‌سازی:

```
گیت‌هاب → ریپو → Add file → Create new file
نام فایل:  .github/workflows/publish-approved-content.yml
محتوا:     کل محتوای فایل
           "استودیوی تبلیغات و بازاریابی/scripts/publish-approved-content.yml"
           را کپی کن و اینجا بچسبان
Commit
```

### ب) کلید Zernio را به‌عنوان رمز مخفی بگذار

```
گیت‌هاب → ریپو → Settings → Secrets and variables → Actions
→ New repository secret
   Name:  ZERNIO_API_KEY
   Value: همان کلیدی که در برنامهٔ بازاریابی وارد کردی
```

**کلید را در چت نفرست و در فایل نگذار.** فقط در همان صفحهٔ گیت‌هاب.

### ج) شناسهٔ حساب‌ها را هم بگذار

```
ZERNIO_ACCOUNT_INSTAGRAM   → شناسهٔ حساب اینستاگرام
ZERNIO_ACCOUNT_FACEBOOK    → شناسهٔ صفحهٔ Bazino pro
```

شناسه‌ها را با این دستور می‌گیری (کلید را خودت جای `$ZERNIO_API_KEY` بگذار):

```powershell
curl https://zernio.com/api/v1/accounts -H "Authorization: Bearer $env:ZERNIO_API_KEY"
```

---

## ۳. اینستاگرام را وصل کن

الان در Zernio **فقط صفحهٔ فیسبوک «Bazino pro»** وصل است. تا اینستاگرام وصل نشود،
ورک‌فلو فقط به فیسبوک می‌فرستد.

برای وصل کردن: طبق مستندات Zernio، آدرس `GET /v1/connect/instagram` با `profileId`
صدا زده می‌شود و مالک حساب در مرورگر خودش وارد می‌شود. **ورود را خودت انجام بده؛ من
رمز، کوکی یا کد ورود نمی‌بینم و در گیت ثبت نمی‌کنم.**

نکتهٔ مهم از مستندات: حساب اینستاگرام باید **Business یا Creator** باشد. حساب شخصی
از طریق رابط برنامه‌نویسی اجازهٔ انتشار ندارد.

## ۴. یک پوشهٔ محتوا چطور ساخته می‌شود

```
Work/publish/2026-09-30-family-carousel/
├── publish.json          ← تأیید، متن، رسانه، حساب‌ها
├── slide-1.jpg
├── slide-2.jpg
├── …
└── notes.md              ← اختیاری: چرا این محتوا ساخته شد
```

### نمونهٔ `publish.json`

```json
{
  "approved": true,
  "approvedBy": "paymanshafayan",
  "approvedAt": "2026-09-30T19:10:00Z",
  "claimsVerified": true,
  "platforms": ["instagram", "facebook"],
  "accountIds": {
    "instagram": "IDENTIFIER_FOR_INSTAGRAM",
    "facebook": "IDENTIFIER_FOR_FACEBOOK"
  },
  "content": "متن کپشن… ۳ تا ۵ هشتگ اندازه‌بندی‌شده در انتها",
  "media": [
    { "type": "image", "path": "slide-1.jpg" },
    { "type": "image", "path": "slide-2.jpg" }
  ],
  "scheduledFor": "2026-09-30T18:00:00.000Z"
}
```

### قواعدی که اسکریپت خودش چک می‌کند و رد می‌کند

| شرط | اگر برقرار نباشد |
|---|---|
| `approved` باید `true` باشد | انتشار نمی‌شود |
| `approvedBy` و `approvedAt` باید باشد | انتشار نمی‌شود |
| تأیید نباید older از ۷ روز باشد | انتشار نمی‌شود، باید دوباره تأیید کنی |
| `claimsVerified` باید `true` باشد | انتشار نمی‌شود |
| `media` نباید خالی باشد | انتشار نمی‌شود (اینستاگرام پست فقط-متنی را رد می‌کند) |
| `accountIds` برای هر پلتفرم باید باشد | انتشار نمی‌شود |

---

## ۵. اجرا

```
گیت‌هاب → تب Actions → Publish approved content → Run workflow
   package:  Work/publish/2026-09-30-family-carousel
   platforms: instagram,facebook
   dry_run:  true        ← اول همیشه این
```

خروجی را بخوان. اگر درست بود، دوباره اجرا کن با `dry_run: false`.

بعد از یک انتشار واقعی، **شناسهٔ پست و لینکش را در همان پوشهٔ محتوا بنویس** تا مدرک
بماند.

---

## ۶. دو نکتهٔ فنی که باید بدانی

۱. **رسانه باید از آدرس عمومی قابل دسترسی باشد.** اینستاگرام فایل را از آدرس می‌گیرد،
   نه از رایانهٔ تو. لینک‌های Google Drive و Dropbox و OneDrive کار نمی‌کنند چون صفحه
   برمی‌گردانند نه فایل. برای همین اسکریپت مسیر `/v1/media/presign` را دارد که فایل
   را مستقیم آپلود کند — **اما شکل دقیق درخواست presign باید یک بار از مستندات Zernio
   تأیید شود.** تا آن زمان، مطمئن‌ترین راه این است که رسانه روی میزانی عمومی باشد و
   آدرسش را در `url` بگذاری.
۲. **سهمیهٔ انتشار:** یک حساب اینستاگرام در هر ۲۴ ساعت حداکثر ۱۰۰ پست. برای ما مهم
   نیست، ولی اگر خطای سهمیه دیدی، دلیلش این است.

---

## ۷. چه چیزی هنوز آماده نیست

- **اجرای واقعی هنوز آزموده نشده.** تا کلید مخفی و شناسهٔ حساب‌ها و اتصال اینستاگرام
  برقرار نشود، فقط dry run کار می‌کند.
- **شکل دقیق presign** نیاز به تأیید مستندات دارد (نکتهٔ ۶).
- **من نمی‌توانم فایل ورک‌فلو را بسازم.** یک بار خودت می‌سازی (بند ۲-الف).
