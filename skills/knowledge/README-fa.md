## چرا اسکیل و نه سند ساده

اسکیل می‌تواند فایل‌های مرجع، توضیح frontmatter و ترتیب بارگذاری داشته باشد.
سند تخت نمی‌تواند.

## چه زمانی بارگذاری می‌شود

⚠️ برخلاف §۳۱، این بخش **همیشه در حافظه نیست.** فقط **در ابتدای ماموریت** و فقط
اسکیل همان ماموریت خوانده می‌شود.

## چرخه سه مرحله‌ای

```
۱. بررسی: آیا skills/knowledge/<ماموریت>/ وجود دارد؟
۲. اگر نه → 🔍 اول گیت‌هاب، بعد وب → ادغام → ساخت اسکیل
۳. اگر بله → بارگذاری کامل و استفاده در طول ماموریت
```

### چرا اول گیت‌هاب

اسکیل‌های ایجنت آنجا به‌شکل مستقیماً قابل استفاده منتشر می‌شوند، و **بازخورد
قابل اندازه‌گیری است**: ستاره، فورک، ایشوهای باز، تازگی کامیت‌ها.

| سیگنال | چه می‌گوید |
|---|---|
| ستاره و فورک | میزان پذیرش |
| تاریخ آخرین کامیت | آیا هدف متحرک را دنبال می‌کند |
| ایشوهای باز/بسته | آیا نویسنده نگهداری می‌کند |
| دقت README | کار واقعی یا مزرعه کلیدواژه |
| مجوز | آیا مجاز به استفاده‌ایم و با چه شرطی |

## بررسی ماهانه کهنگی — خودکار

هر شب پس از اعلام پایان کار توسط مالک، **همه اسکیل‌های این پوشه بررسی می‌شوند.**
این کار **بدون اجازه** انجام می‌شود (دستور مالک، ۲۰۲۶-۰۹-۱۸).

برای هر اسکیلی که بیش از یک ماه از به‌روزرسانی‌اش گذشته:

۱. **اول منبع اصلی** — اگر گیت‌هاب است، کامیت یا ریلیز جدید هست؟ اگر بله، از
   همان منبع به‌روزرسانی شود.
۲. **اگر منبع اصلی تکان نخورده** — جست‌وجوی گسترده‌تر برای منابع تازه‌تر.
۳. **نتیجه در هر صورت ثبت شود** — حتی «بررسی شد، چیز جدیدی نبود».
